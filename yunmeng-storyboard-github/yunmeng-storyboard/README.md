# 云梦·AI分镜导演

**编导云梦 · yunmeng-storyboard**

把中文剧本整理成可制作的 AI 分镜：先讲清每个镜头要让观众看到什么，再写起始帧、动作过程、声音与镜间衔接。

适用于 AI 短剧、校园喜剧、其他叙事短片，以及 LibTV 等制作流程中的分镜准备与修改。题材、角色和模型服从当前项目，不固定为某一部剧。

## 可以做什么

| 你提供的任务 | 技能交付的内容 |
| --- | --- |
| “给这部剧写 AI 分镜预设” | 全片风格、人物与场景连续性规则、可复用单镜格式 |
| “把这一段拆成分镜” | 镜头表、景别、机位、动作、对白、时长和接点 |
| “写每镜的生成提示词” | 分开的静态起始帧、视频动作、发声轨、结束状态与剪辑说明 |
| “这几张图有没有穿帮” | 根据实际画面定位问题，给出局部修正方案 |
| “检查镜头能不能接上” | 对照人物位置、视线、左右手、道具归属与动作阶段 |

它是一份供 AI 助手使用的技能包，并非独立的视频生成软件。图片、视频生成及外部平台操作，需要所在工具具备相应能力。

## 开始使用

将完整目录导入支持 `SKILL.md` 技能的 AI 工具，并按该工具的说明启用；保留 `references/`、`assets/`、`scripts/` 和 `agents/` 的相对位置。

启用后可以这样提出任务：

> 使用云梦·AI分镜导演，处理下面这段剧本。保持已确认的情节和台词，先给分镜表，再分别写静态起始帧与视频动作提示词。附件中的素材才是现有资产，缺失的列出来，不要虚构参考图编号。

支持 `$技能名` 调用方式的工具中，可使用 `$yunmeng-storyboard`。

### 只要整体预设

> 用云梦分镜技能，为这部校园恋爱喜剧写 AI 分镜提示词预设。搞笑为主、恋爱慢慢推进，只给通用规则和单镜模板，暂时不要展开整集。

### 要完整分镜与提示词

> 用云梦分镜技能，把这段剧情拆成约 20 秒的分镜。甲把相机交给乙，乙看了一眼后屏，发现镜头盖没摘。保留这个事件，台词自然，交接动作要连续。当前没有角色图和相机参考图，请先交文字草案与缺失资产清单。

### 只检查穿帮

> 检查附件中前后两镜：相机由谁拿、哪只手托着、镜头和后屏朝哪边，人物有没有换座。只说明看得见的问题，给最小修改方案；看不清的标待核实。

## 这份技能着重解决的问题

- **资产不能凭空出现。** 区分缺失、已有未验收、已验收；没有真实参考图和输入顺序，就不写“已绑定 Image 1”。
- **起始帧只是一瞬间。** “伸手准备接相机”和“已经接过相机”是不同状态，不能把结果提前画进起始帧。
- **演员动作和摄影机运动分开写。** 谁走、摄影机怎么跟、在哪里停，要能实际执行。
- **场景位置和画面左右分开记。** 反打可以改变画面左右，但不能让人物无缘无故换座。
- **笑点有因果。** 从人物目标、误会与后果设计铺垫和回扣，不靠硬塞流行语。
- **声音有明确归属。** 发声台词、中文理解用译文、画外声和剪辑声音分别说明。
- **参数以实际平台为准。** 不把 Midjourney 参数塞进其他视频模型，也不承诺提示词能保证分辨率或生成时长。

## 包含的内容

| --- | --- |
| `SKILL.md` | AI 助手读取的主入口与工作流程 |
| `agents/openai.yaml` | 支持该格式的工具使用的显示与调用信息 |
| `assets/storyboard-template.md` | 项目预设、镜头表、单镜生成卡、审查表 |
| `assets/continuity-example.json` | 两镜交接相机的结构化示例 |
| `references/directing-decisions.md` | 叙事、受众、节奏、伏笔、人设与情绪决策 |

| `references/acceptance.md` | 交付与画面检查清单 |
| `references/model-adapters.md` | 模型适配原则及附核验日期的参数纠错 |
| `references/lexicon-use.md`、`references/lexicon.json` | 描述词使用指南与可检索词库 |
| `references/source-decisions.md`、`references/source-fingerprints.json` | 资料来源定位、规则冲突处理与文件指纹 |
| `scripts/lookup_terms.py` | 按关键词与类别查询词库 |
| `scripts/check_storyboard.py` | 检查显式时长、资产引用和声明的镜间状态 |

## 词库

由 20 份参考资料整理规则，其中 7 份表格形成 **1,125 条去重条目**。条目保留原文件、工作表与单元格来源，便于回查；原始 DOCX、XLSX 未包含在本包中。

| 类别 | 检索名称 | 条数 |
| --- | --- | ---: |
| 打斗 | `combat` / 打斗 | 88 |
| 镜头 | `camera` / 镜头 | 24 |
| 美学 | `aesthetics` / 美学 | 72 |
| 情绪 | `emotion` / 情绪 | 245 |
| 生动性 | `vivid` / 生动性 | 321 |
| 赛事 | `sports` / 赛事 | 287 |
| 外貌 | `appearance` / 外貌 | 88 |

按镜头任务选少量词，并转成可见动作。词库是创作参考，不能代替专业赛事规则或当前模型文档。

## 可选：在电脑上运行检查工具

两个脚本只使用 Python 3 标准库，无需安装额外 Python 依赖。进入本目录后运行；Windows 若使用 Python Launcher，可将命令开头的 `python` 换为 `py -3`。

查询描述词：

```bash
python scripts/lookup_terms.py 焦虑 --category emotion --limit 5
python scripts/lookup_terms.py 环绕 --category 镜头
python scripts/lookup_terms.py "篮球 运球" --category sports --json
python scripts/lookup_terms.py --list-categories
```

检查示例分镜：

```bash
python scripts/check_storyboard.py assets/continuity-example.json
```

示例总长 10 秒，结构检查通过时仍会提醒“相机参考图缺失”，因为它是纯文字示范。制作项目时先复制示例，填写自己的镜头、资产及状态，再检查该文件。

检查脚本不会分析图片，不会自动发现六根手指、脸部变化或不合理的运镜；`ok: true` 仅表示填写的数据通过了所列检查。

## 上传到你的 GitHub 仓库

1. 解压下载的文件包，打开 `yunmeng-storyboard` 文件夹。
2. 准备一个空仓库，仓库名可用 `yunmeng-storyboard`。
3. 在仓库上传文件入口，上传这个文件夹**里面的文件和子文件夹**，保留目录结构。已有文件列表的页面可从 **Add file → Upload files** 进入。
4. 检查仓库首页能直接看到 `README.md` 和 `SKILL.md`，再提交上传。

上传的是解压后的内容；只上传 ZIP，GitHub 不会自动把它展开成技能目录。界面操作参考 [GitHub 官方上传说明](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。

仓库简介可填写：

> 中文 AI 分镜技能：剧本拆镜、静态起始帧与视频提示词、空间和道具连续性检查，附 1,125 条描述词库。
