# 分镜与生成结果验收

把文本计划自查和实际画面验收分开。没有输出画面时只能检查计划。

## 文本计划

1. **任务与因果**：每镜提供何种信息、人物为什么行动、结果如何引出下一步？有无擅改已批准剧本、突然增加关系亲密度、挪用参考片具体桥段？
2. **时间**：各镜时长之和与要求是否一致？对白在指定语言能否自然说完？动作、反应和呼吸有无时间？成片长度与生成器单次长度是否分开？
3. **起始画面**：是否只有一个时刻？“将要扶杯”是否已抓稳？“准备接相机”是否已由接收者独立持有？建立镜头是否预演后续动作？
4. **镜头设计**：裁切是否能看清核心动作？特写是否塞了画外全身细节？推拉、摇移、变焦、正反打是否混用？运镜有跟随目标与停点吗？
5. **空间与状态**：人物本人左右、画面左右、世界坐标是否区分？接镜有没有无法解释的换手、换座、伤痕换边、道具开封、昼夜或光向变化？时间省略是否明确？
6. **资产与技术**：存在、看过、验收通过是否分别记录？缺参考是否伪造编号？参数是否属于所用模型和当前版本？
7. **声音**：发声语言与理解用译文是否区分？声音和声源的揭示顺序是否有作用？字幕开关是否与有声对白混淆？

## 实际画面/视频

- 放大看与故事有关的脸、眼镜、手、鞋和物件。只能判可见部分，遮挡下的手不凭空数指。
- 观察连接/支撑：门连哪根柱、车体和轮胎是否连续接地；椅背、座面和坐姿能否互相解释；镜头朝被摄者、后屏朝持机者或观看者；肩带连机身并自然受力。
- 对照前后时刻核对面貌、服装、方向、背景人数/座次、光源和道具所属，不能只逐张觉得漂亮。
- 视频要看动作之前、接触/转折与动作之后，确认过程实际发生；不把静态图推断为已完成的视频动作。
- 有音轨才核对发声内容和口型；不能播放或识别时标记未核。
- 优先修错误人脸、人物穿墙、道具来源不明、结果提前、车门悬空、轴线混乱；细节噪点或表演幅度按用途处理。

修正时固定已通过的身份、构图和状态，只改定位到的错误；空间骨架不成立时重构机位/物体关系，不反复修饰错误局部。

## 结构工具的边界与格式

`check_storyboard.py` 读取UTF-8 JSON。顶层 `target_duration_seconds` 为目标时长；`assets` 用实际资产名作键，`status` 为 `missing/available/approved`，后两者填写可追溯 `source`，`approved` 另写 `approval_evidence`。这些是人工声明，脚本不做图像识别或联网验证。

`shots` 按剪辑顺序排列，含唯一 `id`、正数 `duration_seconds`，可选 `required_assets`、`reference_bindings`（参考位次到资产名的映射）、扁平 `state_start/state_end` 字典。连续性用同一稳定状态键和同一写法；相邻共享键值不同须在本镜 `transition.changes` 写出该键的变动依据。省略或换场可设置 `transition.type`，并在 `transition.explanation` 给叙事证据。脚本只能检查有无声明，声明是否成立仍须人工核对。

工具不理解物理、对白真实语速、表演是否好笑或角色是否同一张脸，不给“无穿帮”结论。未给状态会有不完整提示。结构化检查是可选增强，不要求把每个简短提示词请求改造成JSON任务。
