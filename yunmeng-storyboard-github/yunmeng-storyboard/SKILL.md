# 云梦·AI分镜导演

把叙事意图变成观众看得见、模型能执行、剪辑能接上的镜头。以用户当前剧本和实际资产为准，按任务规模选择下列流程，交付用户所要的层级。

文中的脚本路径相对于本技能目录；在其他工作目录运行时用绝对路径。用户项目与交付物保存到本次任务的位置，不写回技能目录。

## 先确定交付边界

- 要整体提示词预设：给全片基调、人物/场景连续性规则和可复用单镜格式，不展开整集。
- 要分镜：保留已批准的情节、台词含义和时长，拆成镜头表；必要的补充动作标明“衔接补充”。较大的剧情改写先作为建议呈现。
- 要图/视频提示词：分开写静态起始帧、时间内动作、结束状态和剪辑指令。只需要其中一项时不附整套长文。
- 指出穿帮：先看问题帧及相关前后镜，再说明证据与局部修正；没有画面时给“待核实项”，不宣称已验收。
- 要实际生成：准备好输入后使用当前可用生成工具；制作技能本身不代表已经生成了资产、视频或操作了外部平台。

## 1. 从实际输入建立约束

读取完整相关文本、表格和实际参考图。参考视频按时间顺序查看，说明实际覆盖范围及音轨是否已处理；只有抽帧或字幕时不得声称听完原声。参考片用于分析信息揭示、节奏、表演和镜头关系；原创任务重新设计事件因果，不照搬场景、笑点顺序和台词。

提取本段叙事任务、前后接点、人物目标、受众已知/未知信息、画幅、目标成片时长、对白语言、风格、平台及模型原名。能合理推进的缺项做简短显式假设；涉及身份、剧情分支、参考文件归属等关键歧义才提问。

建立实际资产清单：名称、用途、来源定位、状态（缺失/已有未验收/已验收）。用户说“已上传”可记用户声明，但未看见图不能称视觉验收通过。缺失资产仍可写文字设定和生成草案，最终绑定列为待办。只在当前工具确实接收参考图、且实际选择/上传顺序已知时生成 `{{Image 1}}` 等编号映射；否则用实际资产名并注明待绑定。不要编出“已验收母图”。

用户资产库里有图，不等于本镜已选中该图。最终检查提示词中的“已绑定/已验收”等完成态措辞；实际待绑定的方案明确标为草案，补齐输入后才称可直接执行。剧情必须显示的照片未提供时，可列后期贴屏方案，但占位画面不能算已兑现该信息。

对连载先列当前版本沿用与废弃项。只在当前项目中使用已确认的人物、痕迹、服装、杯子、座位等；不把旧集已取消道具带回来，不把试做头像发色自动写入正片。用户新的明确决定优先。

## 2. 按信息变化设计镜头

剧情、节奏、喜剧或行为需要设计时，读取 [编导决策](references/directing-decisions.md)。

- 每镜明确观众新增什么信息、情绪或因果，由此选择景别和视点。开场可以直接进入事件，不强制空镜开场。
- 对白是角色当下会说的话，按语言与关系控制称呼、句长、打断和停顿；不让初识人物突然熟络，不用解释性长台词替代可拍出的动作。
- 喜剧检查铺垫、误判、后果、回扣的因果。不要强塞热梗或规定每几秒必须反转；引用“最近热梗”前核实含义和使用环境。
- 不给所有镜头添加多余动作。安静倾听可通过明确视线目标和呼吸成立；需要表演变化时写身体可以完成的过程。
- 区分剪辑镜头数与平台生成片段数；单镜可含自然连续动作。用户指定一镜到底时保留连续时空并检查路线、时长和生成支持，不偷换成多个硬切镜头。

## 3. 锁定空间和状态

涉及拆镜、接镜或穿帮检查时，读取 [景别与连续性](references/shot-and-continuity.md)。

先写世界坐标：门、窗、讲台、道路、家具等固定关系；再写本机位看到的画面左/右、景深层次和遮挡。人物本人左手与画面左侧分开标注。机位变化可以改变画面左右，人物在场景里的位置不能无动作地交换。

用简洁状态账本记录人物位置/朝向/视线、服装和痕迹、物件持有者/哪只手/放置位置/开合状态、光源与背景人物。上镜结束与下镜起始有变化时，交代在镜动作、明确省略或时空转换；瞬时动作可在切点衔接，不要求每镜完成整套动作。

“递相机”分清对方尚未接触、双方共同托持、接收者独立持有；起始帧不预先画成交接完成。车门、椅子、相机肩带等物件，要描述连接、承重和支撑关系，不能只列物件名。

## 4. 翻译成生成输入

使用 [项目与单镜模板](assets/storyboard-template.md)，按任务交付需要的字段。全片共用预设与单镜内容分开管理；单镜需独立粘贴生成时，复制必要的身份、场景、光线约束，不能只写“同上”。

**静态起始帧**：仅描写同一时刻可见的场景、角色、姿态、视线、手与物的接触状态、构图和光线；可以有动作前的姿态，不写先后过程、运镜或对白，不提前画出尚未发生的结果。特写只写裁切内可见细节，完整服装设定留在资产卡。

**视频动作**：给明确起始状态、核心动作过程、结束状态，并给注视对象与克制表演。摄影机单独写起点、方向、速度感、跟随对象和停点；固定机位也直接说明。推拉改变机位，变焦改变视角；正反打属于镜头组织，不是单次运镜。

**声音与剪辑**：标说话者、对白语言、原话、语气和是否画外。理解用的中文译文与模型应发出的台词分开，不让演员读双语两遍。环境音和动作声服务空间与笑点。J/L-cut、匹配切等后期指令单列，不假定单段生成器会执行后期剪辑。无字幕的画面仍可有有声对白。

按需阅读 [词表用法](references/lexicon-use.md)，从 [词库](references/lexicon.json) 获取少量相关词；例如 `python scripts/lookup_terms.py "迟疑" --limit 5`。把词落实为动作，避免同义词堆砌和美学互相抵消。

需要平台参数时才读 [模型适配](references/model-adapters.md)。自然语言风格不能保证实际8K、帧率或零掉帧；分辨率、时长、帧率等真实控件与提示词分开。LibTV 用户写的 `sd2.5` 保留原名，未确认厂商和界面能力前不自动解释成别的模型，不混入 Midjourney flags。

## 5. 交付前作有证据的检查

按 [验收清单](references/acceptance.md) 检查信息与时长、起始状态、动作可执行性、轴线、手与道具归属、物体连接及声音衔接。反馈用“镜号—证据—影响—改法”，优先处理会改变剧情或空间理解的问题。

需要结构化检查时，可参照 [状态账本示例](assets/continuity-example.json) 填写项目数据，运行 `python scripts/check_storyboard.py <项目.json>`。该工具仅核对显式时长、资产引用和声明的状态衔接；仍须人工核对影像、台词时长和物理合理性，不把结构通过称为成片验收。

先交付完整可复制的所需结果，再简短列缺失资产与关键待确认项。不为例行步骤设置审批，避免反复重生已足够好的内容。未实际看到、生成、验收的项目如实保留状态。

## 来源与规则裁决

本技能将20份用户资料转成可执行规则。资料定位、冲突和适用范围见 [来源与裁决](references/source-decisions.md)。文档案例、经验数值和厂商参数是参考；与用户当前需求冲突时保留用户需求，技术事实按可核实官方资料处理。
